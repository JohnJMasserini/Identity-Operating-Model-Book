# Contributing errata

Thanks for reading closely enough to catch something. Here's how a report
turns into a fix.

## 1. Search first

Check the Wiki for confirmed corrections and updates, and the [open/closed issues](../../issues)
page before filing a new errata. If someone has already reported it, in which case, a 👍
on the existing issue is more useful than a duplicate.

## 2. Open an Errata Report issue

Use the **Errata Report** issue template (Issues → New issue → Errata
Report). Include:

- **Location** — page number and, if you know it, the printing/edition
  (check the copyright page). If you're reading a digital edition without
  page numbers, use the chapter and a nearby quote instead.
- **What the book says** — quote the exact text or describe the figure.
- **What's wrong** — the specific error (typo, factual mistake, code that
  doesn't run, a diagram that contradicts the text, a broken reference,
  etc.).
- **Suggested correction** — if you know what it should say.

The more precise the location, the faster this gets triaged.

## 3. Triage and review

Reports move through this process:

1. **Reported** — the default state for a new issue.
2. **Confirmed** — the author has checked the source manuscript/print
   copy and agrees it's an error.
3. Either:
   - **Fixed in printing N** — corrected in a subsequent printing, and
     added to the Wiki, or
   - **Won't fix** — closed with a comment explaining why (e.g., it's a
     stylistic choice, or the "error" is actually correct and the report
     was a misreading).

## 4. What doesn't belong here

- General questions about the book's content — use [Discussions](../../discussions)
  if enabled, not an errata issue.
- Feature requests for a hypothetical second edition — also fine for
  Discussions, but not an errata report.
- Reports on third-party tools/products mentioned in the book that have
  simply changed since publication — file these as an "update" note
  instead of an errata report (see the Post-publication updates section
  of he Wiki); it's not a mistake in the text, just time passing.

## Style for correction text

Keep corrections terse and unambiguous — they should read like a copy
edit, not a discussion. Save the reasoning/debate for the issue thread;
the Wiki should stay skimmable.
